# Pitfalls Research — compress_video

**Researched:** 2026-09-14. Every pitfall below was shipped by the incumbent or a competitor; sources in `sources/issues-and-prs.md` and `sources/competitors-and-native-apis.md`.

| # | Pitfall | Who shipped it | Warning sign | Prevention | Phase |
|---|---|---|---|---|---|
| 1 | Toolchain rot: plugin pins Kotlin/AGP/JVM target and breaks on every Flutter release | incumbent (#142 24👍, #262, #255, #323) | Users hand-edit `~/.pub-cache`; "cut a release" issues | CI matrix on current stable Flutter + AGP; track the AGP-9 built-in Kotlin path; SPM + CocoaPods both; a quarterly "toolchain" chore in the backlog | 1, ongoing |
| 2 | Dependency artifact vanishes (JCenter) | incumbent (#240/#247/#207, 24👍) | Coordinates on a non-Google/Maven-Central repo | Only androidx/Maven Central artifacts; no JitPack | 1 |
| 3 | Errors swallowed into `null` / debugPrint | incumbent (`onTranscodeFailed → result.success(null)`, Dart `_invoke` catch-all) | "returns null" issues | Pigeon typed errors; a test that asserts every failure path returns a `CompressError` with a reason | 1, 3, 4 |
| 4 | Force-unwrap / status never checked on iOS | incumbent (Swift line 203, `exporter.status` unchecked; 19👍) | Crash on iCloud placeholder or damaged MOV | `guard let` + `AVAssetReader.status`/`AVAssetWriter.status` checks with typed errors; corpus includes a damaged file | 4 |
| 5 | Output larger than input | incumbent (#200, SO 67594673), guarded by Twake in app code | Presets defined by resolution only, bitrate estimated | Compare bytes after encode; return original with `usedOriginal: true`; consider input bitrate when choosing target | 3, 4 |
| 6 | "Highest" preset re-encodes 4K at 3.7 Mbps | incumbent (`HighestQuality` = fixed 3,686,400 bps, no resize) | Blocky 4K output | Presets are (maxLongSide, bitrate) pairs; bitrate scales with resolution | 3 |
| 7 | Units differ per platform for the same parameter | incumbent (thumbnail `position`: ms/µs/s; trim seconds vs ms PRs #306) | "same frame at every position" | Pigeon field names carry units; one conversion point per platform; corpus test asserts frame at 5000 ms differs from 0 ms | 1, 2 |
| 8 | Wrong trim semantics | incumbent (`TrimDataSource(start, duration)` where arg 2 is trimEnd; iOS `timeRange` only when audio off) | "10 s of 12 s → 2 s" | Media3 `ClippingConfiguration(startMs, endMs)`; Apple `timeRange` always; test asserts output duration | 3, 4 |
| 9 | Rotation: sideways, doubly rotated, or black bars | incumbent (inverted W/H swap #172/#330; iOS `videoComposition` loses transform #195/#315); `light_compressor_v2` metadata-only | Portrait clip in corpus fails | Media3 default (rotate to landscape + metadata); Apple `writerInput.transform = track.preferredTransform` before `startWriting`; result dims from displayed orientation | 3, 4 |
| 10 | HDR pushed through an SDR pipeline → washed out | incumbent (#298), `light_compressor_v2` (stamps HDR transfer on 8-bit output), `v_video_compressor` (no HDR code), Transcoder (#191 open) | iPhone/Pixel default clips look grey | Media3 `HDR_MODE_TONE_MAP_HDR_TO_SDR_USING_OPEN_GL`; Apple 8-bit reader output settings (system tone-map) for SDR, Main10 + colour properties for keep-HDR; corpus has Dolby Vision 8.4 and HLG10 clips | 5 |
| 11 | Audio passthrough crashes on device | `light_compressor_v2` 1.9.0 (missing `sourceFormatHint`, 100% repro on real iPhones with `.mov`) | Works in simulator, dies on device | Always pass `sourceFormatHint` when `outputSettings == nil`; run device tests, not only simulator | 4 |
| 12 | 5.1 / PCM / no-audio sources fail | incumbent (#279 "channel count not supported: 6", #198 crash) | `IllegalArgumentException` from muxer | Probe channels; downmix/re-encode when > 2 or non-AAC; handle no-audio track | 5 |
| 13 | Bitrate option that never reaches the encoder | `v_video_compressor` (no `VideoEncoderSettings` in source) | File size unchanged across "bitrates" | `DefaultEncoderFactory` + `VideoEncoderSettings.setBitrate`; integration test asserts output bitrate within tolerance | 3 |
| 14 | Option surface the engine can't honour | `v_video_compressor` (`crf`, x264 presets, `bFrames`, `mp3`) | Options silently ignored | Expose only what both engines do; document per-platform differences | 1 |
| 15 | Global singleton progress stream / one in-flight job | incumbent (`compressProgress$`, `isCompressing`, PR #307) | Batch/concurrent breakage | Per-job streams and registry from day one | 1, 6 |
| 16 | Hard-coded `MethodChannel` → unusable in isolates | incumbent (#242) | `BackgroundIsolateBinaryMessenger` error | Injectable messenger | 6 |
| 17 | iOS export dies when app backgrounds (`-11847`) | everyone; Apple calls it expected | Users report "fails when I switch apps" | Document; surface `interrupted` error; `beginBackgroundTask` for the last seconds; retry guidance | 6 |
| 18 | Foreground service type wrong on Android 15 | `light_compressor_v2` uses `dataSync` | Play policy / runtime restriction | `mediaProcessing` type + permission; handle `onTimeout` | 6 |
| 19 | Transformer thread misuse / concurrent exports on one instance | Media3 docs | Crash under batch | One instance per job on its own thread | 3, 6 |
| 20 | 4K60 exceeds encoder level; >30 fps sources drop frames on Apple | corpus | Encoder init failure / stutter | Query `MediaCodecInfo.VideoCapabilities`; set `AVVideoExpectedSourceFrameRateKey`; cap fps by default | 5 |
| 21 | Thumbnail filenames collide / not rotated | incumbent (#274, PR #331) | Wrong frame shown | Unique names; apply rotation | 2 |
| 22 | pub.dev points lost on docs/platform declarations | incumbent at 140/160 | Score < 160 | dartdoc on all public API, example, `platforms:` declared, analysis clean, SPM | 7 |
| 23 | Undocumented presets ("what does Medium mean?") | incumbent (#60 Default==Medium on iOS) | Support questions | Generate README table from preset constants | 7 |
