<objective>
Port the three pure, framework-free pieces of the Android engine to Swift and prove them with the
same numbers that prove the originals.

Purpose: everything observable about Apple/Android parity — which preset produces which
dimensions, when a transmux is legal, when the never-larger substitution fires, what a failure is
called, where a file may be deleted from — is decided by three files that touch no media API at
all. Porting them first, and pinning them with an XCTest twin carrying the SAME numeric cases as
the Kotlin suite, means a divergence in the plan math fails on the Mac in seconds rather than
surfacing three plans later as an unexplained parity-gate mismatch against a real encode.
Output: `SizeGuard.swift`, `ErrorMapping.swift` and `PluginFiles.swift`, plus case-for-case XCTest
coverage in both byte-identical `RunnerTests.swift` copies, green on the iOS simulator and the
macOS host.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller-supplied path → filesystem | `PluginFiles.sweep` and the cache-directory resolution decide which files this plugin is allowed to delete; a path that escapes the intended directory crosses a real boundary inside the host app's sandbox |
| platform error object → typed reason | An `AVError`/`NSError` produced by AVFoundation is untrusted structured data that the plugin converts into an API-visible reason string |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-06 | Tampering | `PluginFiles.sweep` following a symlink out of the cache directory and deleting a file the plugin does not own | high | mitigate | `sweep` resolves every candidate's symlinks with `Arguments.swift`'s existing idiom and refuses anything whose resolved path is not under the resolved cache directory; a real on-disk symlink escape case in `RunnerTests.swift` proves the refusal rather than asserting it |
| T-03-07 | Tampering | `sweep` recursing into a sibling or nested directory and widening its blast radius | medium | mitigate | Only the immediate directory contents are listed; the acceptance criteria grep proves no recursive enumeration API is used, and an XCTest case plants a file in a subdirectory and asserts it survives |
| T-03-08 | Information Disclosure | A failure message leaking a user's file path into the API surface or a log | medium | mitigate | `ErrorMapping` folds only the error domain and numeric code into the message, never a path; no new code path calls `print`, `NSLog` or `os_log` |
| T-03-09 | Denial of Service | An unmapped `AVError` silently degrading to `unknown` and hiding a real, actionable failure class | medium | mitigate | `knownAVErrorCodes` is asserted for size by a test, so adding a case to the switch without adding it to the set — or the reverse — fails on the Mac |
| T-03-SC | Tampering | Third-party package supply chain | low | accept | This plan adds no package from any registry; the only new code is first-party Swift compiled from this repository |
</threat_model>
