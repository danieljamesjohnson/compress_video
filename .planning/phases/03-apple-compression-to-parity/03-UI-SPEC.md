# Phase 3 — UI Design Contract

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Scope note:** The plugin itself has no UI. The only UI surface in this phase is the Flutter
**example app** (BULD-04) — a single Dart widget tree shared, unmodified, by Android, iOS and
macOS. This contract governs `example/lib/main.dart` only. It is a developer-facing demo for a
pub.dev plugin, not a consumer product: no brand palette, no custom design system — every value
below is Flutter's stock Material 3 `ThemeData` default (`useMaterial3: true`, no explicit
`colorScheme`/`textTheme` override), switching light/dark via `themeMode: ThemeMode.system`.
Where 03-CONTEXT.md's "Example app (BULD-04)" section already locked a decision, it is marked
"Source: 03-CONTEXT.md" below and not re-litigated. Autonomous run: every open choice below was
resolved to the Material-3-default / lowest-novelty option and is flagged **(auto-selected)** —
override freely.

## Design System

| Property | Value |
|----------|-------|
| Tool | none — Flutter/Dart project; shadcn is a React registry tool and does not apply |
| Preset | not applicable |
| Component library | Flutter Material (`useMaterial3: true`, the SDK default since Flutter 3.16 — no `components.json`, no third-party widget package found in `example/pubspec.yaml`) |
| Icon library | `Icons` (Material Symbols bundled with the Flutter SDK). `cupertino_icons` is present in `example/pubspec.yaml` from the stock template but is **not used** by this screen — do not introduce Cupertino widgets; Material-only on all three platforms keeps one widget tree truly shared (BULD-04's own requirement) |
| Font | No custom `fontFamily` declared — Flutter's Material 3 default font resolution (Roboto via Flutter's bundled fallback, identical rendering on Android/iOS/macOS) |

No `colorScheme:` override — Flutter synthesizes the Material 3 baseline `ColorScheme.fromSeed`
(the SDK's own default seed) for both light and dark. This is the entire "palette decision" for
this phase: there isn't one to make.

## Spacing Scale

Declared values (must be multiples of 4) — Material 3's own 4/8dp grid, used directly as Flutter
logical pixels (`EdgeInsets`/`SizedBox`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon-to-label gaps inside a `Chip`/badge, `Row` spacing between inline stat pairs |
| sm | 8px | Compact spacing: between a field and its inline helper/estimate text, between stacked badges |
| md | 16px | Default: screen `EdgeInsets.all(16)`, gaps between form fields, gap between Compress and Cancel buttons |
| lg | 24px | Section padding inside `Card`s (options panel, result card), gap above/below the progress section |
| xl | 32px | Gap between major screen sections (picker → options → progress/result) on phone |
| 2xl | 48px | Also Flutter's `kMinInteractiveDimension` — see touch-target exception below |
| 3xl | 64px | Top padding above the empty-state illustration/icon before a video is picked |

Exceptions: Material widgets (`ElevatedButton`, `IconButton`, `Chip`, `SegmentedButton`) enforce
a **48px minimum tap target by default on every platform** (`kMinInteractiveDimension`), not
iOS's 44pt — because this app is Material-only (no Cupertino), so the touch target is uniform
across Android/iOS/macOS out of the box. Do not shrink below this; do not special-case 44px for
iOS.

## Typography

Material 3's own default `TextTheme` roles (Flutter `Typography.material2021`), used unmodified
— exactly 4 sizes, exactly 2 weights, both already how Material 3 assigns weight (labels get
500, everything else gets 400):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 16px (`bodyLarge`) | 400 (regular) | 1.5 (24/16) |
| Label | 14px (`labelLarge`) | 500 (medium) | 1.43 (20/14) |
| Heading | 22px (`titleLarge`) | 400 (regular) | 1.27 (28/22) |
| Display | 24px (`headlineSmall`) | 400 (regular) | 1.33 (32/24) |

Usage:
- **Body** (`bodyLarge`, 400): field labels, result-card row text ("1280 x 720 px", "Elapsed: 1834 ms"), estimate line, error/empty-state body copy.
- **Label** (`labelLarge`, 500): every button label (`ElevatedButton`/`OutlinedButton`/`SegmentedButton` — this is their Material 3 default text style, not a custom one), `Chip` badge text.
- **Heading** (`titleLarge`, 400): the `AppBar` title ("compress_video example") and the two section headers ("Options", "Result").
- **Display** (`headlineSmall`, 400): the single large "‑42% smaller" savings figure at the top of the result card — the one number this screen wants to be glanceable.

## Color

Material 3 baseline `ColorScheme` roles (no seed override — see Design System). Roles named
here are Flutter `ColorScheme` properties, resolved per-platform automatically for light/dark:

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `colorScheme.surface` | `Scaffold` background, the screen's base surface |
| Secondary (30%) | `colorScheme.surfaceContainer` / `Card` default surface-tint | Options panel `Card`, result `Card`, the picked-clip preview tile |
| Accent (10%) | `colorScheme.primary` | Reserved for exactly: the "Pick video" button fill (idle state), the "Compress" button fill (ready state — never shown at the same time as "Pick video"), the selected segment in the preset `SegmentedButton`, the active track of `LinearProgressIndicator` during compression (Material 3's own default progress-indicator color — not overridden), and the success checkmark icon in the result card header |
| Destructive | `colorScheme.error` / `colorScheme.errorContainer` | Reserved for: the failed-state `Card` (background `errorContainer`, text/icon `onErrorContainer`), the validation-error `SnackBar` background when `CompressOptions.validate()` throws `unsupportedInput` |

Accent reserved for: **only** the two mutually-exclusive primary CTA fills, the selected preset
segment, the in-flight progress bar, and the done-state success icon — never applied to
secondary actions (Cancel, Try again, the "use bundled clip" fallback link), which stay on
Material's neutral `outline`/`onSurfaceVariant` default styling.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA (idle) | "Pick video" |
| Primary CTA (ready) | "Compress video" |
| Empty state heading | "No video selected" |
| Empty state body | "Pick a video from your library, or use the bundled sample clip to try compression without one." (second sentence is a text-button: "Use bundled sample clip →" — this is the corpus-clip fallback 03-CONTEXT.md requires for simulator/emulator/CI runs) |
| Error state (compression failure) | Heading "Compression failed." Body: "{reason} — {next step}", e.g. "Encoder unavailable — try a different preset or pick another clip." `reason`/`nextStep` are derived from `CompressVideoException.reason` (auto-selected mapping table below); button: "Try again" |
| Error state (validation, e.g. contradictory targetSizeMb + videoBitrateBps) | `SnackBar`: "{message}" — the exact string from the thrown `CompressVideoException.message` (`CompressOptions.validate()` already writes a specific, actionable sentence per field; the UI does not rewrite it) |
| Error state (estimate unavailable) | Inline, non-blocking: "Estimate unavailable — Compress still works." (never blocks the Compress button) |
| Error state (playback unavailable) | Inline `bodyLarge` line in place of the player, result card unchanged: "Playback unavailable — the compressed file was still written." **(auto-selected)** |
| Destructive confirmation | "Cancel compression": **no confirmation dialog** — Cancel acts immediately, then a `SnackBar` reads "Compression cancelled." **(auto-selected)** Rationale: cancelling only discards in-progress encode work (JOBS-02: partial output file is deleted); it never touches the caller's original input or an already-completed prior result, so a blocking confirm dialog would slow the one workflow (Compress → watch → Cancel to try different options) this demo exists to show |

**Reason → copy mapping (auto-selected, one line per `CompressVideoErrorReason` this phase can
surface — CDEC-01/02/03 and JOBS-05's `interrupted` are out of scope per 03-CONTEXT.md):**

| Reason | Body copy |
|--------|-----------|
| `unsupportedInput` | "This file or option combination isn't supported — try a different clip or preset." |
| `decoderUnavailable` | "This device can't decode that file's video track — try a different clip." |
| `encoderUnavailable` | "The encoder isn't available right now — try again in a moment." |
| `outOfSpace` | "Not enough free storage to finish — free up space and try again." |
| `io` | "Something went wrong writing the file — try again." |
| `cancelled` | (not an error path — routes to the Cancelled state, not the failed state) |

## Screen States

Seven states per the objective, all in one screen (no navigation/routes) driven by local
`StatefulWidget` state plus `CompressJob`. Column = what's visible; `—` = not rendered (not
merely hidden/disabled).

| State | Picker area | Options panel | Estimate line | Progress section | Result card | Video player |
|-------|-------------|----------------|----------------|-------------------|--------------|--------------|
| **Idle** (no clip picked) | Empty state (heading/body/"Pick video" + "Use bundled clip") | — | — | — | — | — |
| **Picking** (async `image_picker`/`file_selector`/asset-copy call in flight) | "Pick video" button shows an inline 16px `CircularProgressIndicator` in place of its icon, disabled | — | — | — | — | — |
| **Estimating** (clip picked or options just changed; debounced 300ms **(auto-selected)**, then `estimate()` in flight) | Picked-clip preview tile (filename + size) | Enabled, editable | "Estimating…" with 12px spinner | — | — (prior result, if any, stays visible until Compress is pressed again) | — |
| **Compressing** (`CompressJob` running) | Picked-clip preview tile | **Disabled** (Material's default disabled-opacity look — no custom greying) | Last resolved estimate stays visible, frozen | `LinearProgressIndicator(value: progress/100)` + "{percent}%" (`labelLarge`) + enabled "Cancel" `OutlinedButton` | — | — |
| **Cancelled** (transient) | Picked-clip preview tile | Re-enabled | Re-shown for current options | Cleared to 0 / hidden | `SnackBar` "Compression cancelled.", no result card | — |
| **Failed** | Picked-clip preview tile | Re-enabled | Re-shown | Cleared | `errorContainer`-tinted `Card`: "Compression failed." + reason/next-step + "Try again" | — |
| **Done + playing** | Picked-clip preview tile | Re-enabled | Re-shown | Cleared | `Card`: `headlineSmall` "‑{percent}% smaller", then `bodyLarge` rows (bytes before→after, WxH, codec, elapsed) and a `Chip` row (`transmuxed`/`usedOriginal`/`audioReencoded` — only the true ones render, as informational `Chip`s, `secondaryContainer` background, never accent-colored) | `AspectRatio(aspectRatio: widthPx/heightPx)` wrapping `VideoPlayer` + tap-to-toggle play/pause overlay (`video_player`'s own common pattern) |

Notes:
- "Compress video" (ready-state CTA) is shown whenever a clip is picked and not currently
  compressing — i.e. during Estimating, Cancelled, Failed and Done, not only a bare "ready"
  state; it's folded into every row above via "Options panel: enabled" implying the button is
  present and enabled next to it.
- A validation failure from `CompressOptions.validate()` (thrown synchronously, before the
  platform channel) never reaches Compressing — it shows the validation `SnackBar` from Idle/
  Estimating and the screen stays exactly where it was.

## Layout

One shared widget tree, no platform branching beyond the picker's own `image_picker`/
`file_selector` auto-routing (03-CONTEXT.md). Responsive via a single width check, not a second
layout:

- **Phone width** (Android/iOS, ~360–430dp): full-bleed `ListView` with `EdgeInsets.all(16)`
  (`md`), sections stacked vertically in the order Picker → Options → Estimate → Progress/Result
  → Player, separated by `xl` (32px) gaps. Buttons are full-width (`SizedBox(width: double.
  infinity, child: ElevatedButton(...))`) — standard Material phone-form pattern, no bespoke
  layout.
- **macOS desktop width** (window ≥ 600px — `MediaQuery.sizeOf(context).width`, **auto-
  selected** breakpoint at Material's own `600` layout-size boundary): the identical column,
  wrapped in `Center(child: ConstrainedBox(constraints: BoxConstraints(maxWidth: 640), child:
  ...))` so content doesn't stretch edge-to-edge in a resizable desktop window; buttons revert to
  intrinsic width (`Row` with `MainAxisAlignment.start`, not full-width) since a resizable
  desktop window makes a full-width button look stretched. No multi-column layout, no sidebar —
  same single-column widget tree, same order, same spacing tokens.
- Below 600px width (small phones / narrow multi-window on macOS) uses the phone layout
  unconditionally — there is no third breakpoint.

| Element | Category | Status | Resolution |
|---------|----------|--------|------------|
| picker-button | loading | resolved (explicit) | While the pick call is in flight the button's `onPressed` is `null` and its leading icon is replaced by a 16px `CircularProgressIndicator`; the "Use bundled sample clip" text button is also disabled |
| picker-button | error | resolved (explicit) | A picker that returns `null` (user dismissed, permission denied) or throws leaves the screen in the Idle empty state: heading "No video selected" is visible and no error card or snackbar is shown |
| picker-button | long-text | resolved (explicit) | Button labels are the fixed strings "Pick video" / "Compress video" / "Use bundled sample clip →" from the Copywriting Contract; no dynamic text is rendered inside the button |

| options-panel | loading | resolved (explicit) | While a `CompressJob` is running every field in the panel is `enabled: false` (Material default disabled styling) and the primary CTA is hidden; the panel is re-enabled on every terminal state (Done, Failed, Cancelled) |
| options-panel | error | resolved (explicit) | A `CompressVideoException` thrown synchronously by `compress()` / `estimate()` (reason `unsupportedInput`) shows a `SnackBar` whose text is exactly `exception.message`; the screen state does not change and no progress section appears |
