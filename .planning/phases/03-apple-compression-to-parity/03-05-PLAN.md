<objective>
Add the two fast paths and the three audio modes that make the Apple engine behave like the
Android one on every clip that is not a plain re-encode.

Purpose: the engine's headline guarantees are not about encoding well — they are about not
encoding at all when encoding would not help, and about never handing back a bigger file. Phase 2
found two real bugs in exactly this area on Android (an unreachable transmux fast path and a
muxer padding a short remux past its own input size) and shipped an unconditional post-check as
the answer. The Apple engine has the same two shapes of risk with different APIs, so the same
unconditional rule and the same measured proof apply. Audio joins them here because passthrough
is the audio-side equivalent of a transmux and shares the same "only re-encode when you must"
logic.
Output: the transmux branch, the two-stage never-larger rule, the three audio modes, and
`compress_audio_test.dart` green on both Apple platforms with `compress_test.dart` green except
its trim case.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| encoder output → delivered file | The bytes the platform produces decide whether the plugin's own never-larger guarantee holds; the encoder is not under this code's control |
| plugin → caller's input file | The substitution path reads the caller's original and must never write to it or hand its path back |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-20 | Tampering | The caller's original input being returned as the output path, so that deleting the "output" destroys the source | high | mitigate | The substitution always copies into the plugin-owned destination; an integration case asserts the returned path differs from the input path while the bytes match by digest |
| T-03-21 | Denial of Service | A remux silently growing the file past its input and filling the user's disk over repeated calls | high | mitigate | The post-check is unconditional on every branch and compares real measured bytes; the export session runs with network-use optimisation off so no moov-first rewrite can pad a short remux |
| T-03-22 | Tampering | A rejected temp file left behind after a substitution, accumulating in the cache directory | medium | mitigate | The rejected temp file is removed with the quiet-delete helper on the same code path that performs the substitution, and `clearCache()` sweeps the directory as a second line of defence |
| T-03-23 | Denial of Service | A passthrough of an audio format the MP4 container cannot carry, producing an unplayable file that a caller ships to users | medium | mitigate | Passthrough is chosen only after checking the source track's media subtype; anything else falls back to an AAC re-encode and says so in the result |
| T-03-SC | Tampering | Third-party package supply chain | low | accept | This plan adds no package from any registry |
</threat_model>
