<objective>
Turn the example app from a Phase 2 manual-check screen into the real demo BULD-04 describes, on
one shared widget tree, and cover it with a widget test that needs no device.

Purpose: the example app is the only thing a pub.dev visitor actually runs, and it is also this
phase's manual-UAT vehicle for 02-UAT.md #6. It exercises the public Dart API exactly as a
consumer would — `compress`, its progress stream, `cancel`, `estimate`, the typed result and the
typed errors — so a defect in the API's shape shows up here before it shows up in someone's app.
It depends only on the Dart surface, which already exists, so it is built in parallel with the
Swift engine rather than behind it.
Output: a rewritten single-screen example app implementing 03-UI-SPEC.md exactly, the two picker
and player dependencies with their iOS and macOS permissions, and a widget test that drives all
seven screen states through an injectable runner on Linux.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user photo library / file picker → app | The user selects an arbitrary file; its path and contents are attacker-influenced from the plugin's point of view, and on macOS the selection is what grants the sandbox its read access |
| plugin output file → video player | The compressed file is handed to a decoder in the same process |
| pub.dev → example app build | Two new federated plugin families enter every Android, iOS and macOS build of the example |
