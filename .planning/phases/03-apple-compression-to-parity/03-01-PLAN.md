| ID | Decision (abridged from 03-CONTEXT.md `<decisions>`) |
|----|------|
| D-01 | Engine: `AVAssetReader` + `AVAssetWriter` for every re-encode (H.264 via `AVVideoCodecType.h264`, `AVVideoAverageBitRateKey`, `AVVideoWidthKey`/`AVVideoHeightKey`, AAC via `kAudioFormatMPEG4AAC`); `AVAssetExportSession` with `AVAssetExportPresetPassthrough` ONLY for transmux. The export-session progress API is never used for a re-encode. |
| D-02 | One shared Swift core in `darwin/compress_video/Sources/compress_video/`, files mirroring the Android names one-to-one: `SizeGuard.swift`, `CompressionEngine.swift`, `JobRegistry.swift`, `ErrorMapping.swift`, `PluginFiles.swift`, `Compression.swift`. `SizeGuard.swift` gets an XCTest twin with the SAME numeric cases as `SizeGuardTest.kt`. |
| D-03 | Orientation: read BGRA; do NOT bake rotation into pixels; `AVAssetWriterInput.transform = sourceTrack.preferredTransform`; encode at the CODED target size (displayed target swapped back for 90/270); result `widthPx`/`heightPx` from a re-probe of the finished file through `Probe.swift`. `_expectUprightAndUnpadded` must pass unchanged. |
| D-04 | Frame-rate cap: drop frames in the reader loop by presentation timestamp (`pts >= nextKeepTime`, advance by `1/effectiveFps`); `effectiveFps = min(maxFps, input fps)`; never upscale. |
| D-05 | Transmux: `AVAssetExportSession(preset: AVAssetExportPresetPassthrough)`, `outputFileType = .mp4`, `shouldOptimizeForNetworkUse = false`; progress reported 0 → 100 at completion; `transmuxed: true`. |
| D-06 | Never-larger: pre-check via `SizeGuard.Plan.wouldUseOriginal`; post-check unconditional, `usedOriginal = outputBytes >= inputBytes`, on every path including transmux; the original is copied into the plugin-owned output path. `outputPath` never names the caller's input file. |
| D-07 | Audio: passthrough = writer input with `outputSettings: nil` + `sourceFormatHint`, fed by a reader output with `outputSettings: nil`, only when the source track is AAC; otherwise an AAC re-encode reporting `audioReencoded: true`. `reencode(bitrateBps, channels)` decodes to PCM and writes AAC. `strip` adds no audio input. |
| D-08 | Progress and cancel: progress derived from the writer loop (last appended video sample pts over the trim-aware output duration), clamped 0..99, forwarded on the main queue at most every 250 ms, with a single terminal `100` before the result reply. Cancel sets a flag the loop checks per sample, cancels the writer/export, deletes the partial file, completes `cancelled`; cancelling a finished job is a no-op. |
| D-09 | Threading: each job's copy loop runs on its own serial `DispatchQueue`; Pigeon replies and `onProgress` hop to the main queue. `JobRegistry` is main-queue-confined, holds the cancel closure and temp path, and exposes `liveTempFilePaths()`. Teardown cancels every live job BEFORE tearing down registrations (T-02-25). |
| D-10 | Error mapping: `ErrorMapping.swift` maps reader/writer failures and `AVError` codes onto the existing `CompressVideoErrorReason` names; missing file → `fileNotFound` (symlinks resolved); `.diskFull` plus a pre-flight `volumeAvailableCapacityForImportantUsage` check against 1.2x predicted bytes → `outOfSpace`; everything else → `io` with the `NSError` domain/code folded into the message. Claude's-discretion items resolved during planning, recorded once so no executor re-decides them:

- **`SizeGuard`, `ErrorMapping` and `PluginFiles` are Swift `enum` namespaces** with static members, matching the existing `MediaMath.swift` style, and import no AVFoundation (`PluginFiles` imports Foundation only). `JobRegistry` is a `final class` with a shared instance; `Compression` and `CompressionEngine` are `final class`.
- **The reader's video `outputSettings`** carry exactly three keys: `kCVPixelBufferPixelFormatTypeKey` (BGRA), and `kCVPixelBufferWidthKey`/`kCVPixelBufferHeightKey` — and the two size keys are **omitted entirely** when the coded target equals the input's coded size, mirroring Android's "only add the effect if it changes something" rule.
- **Progress cadence stays 250 ms** (Android's number) unless a simulator run shows it materially slows the copy loop, in which case the summary records the measured reason for any change.
- **The macOS integration run uses `flutter test integration_test -d macos`**, not a separate `xcodebuild test` target, so iOS and macOS run byte-identical Dart test code.
- **`trim_source_10s.mp4` carries audio** and no audio-less variant is added; the no-audio branch is already covered by `noaudio_720p.mp4`.
- **The example app's estimate line debounces at 300 ms** (03-UI-SPEC.md's auto-selected value).
- **The free-space pre-check falls back to `volumeAvailableCapacityKey`** when `volumeAvailableCapacityForImportantUsageKey` reports 0 for a directory that demonstrably exists and is writable (03-RESEARCH.md Open Question 3; the key is APFS-only and a caller-supplied macOS `outputPath` can be on another filesystem).
