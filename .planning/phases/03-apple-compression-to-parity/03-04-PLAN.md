iOS simulator and the macOS host.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Dart caller → native host API | Every argument — the input path, the job id, the output path, every option — arrives from the host app and is untrusted until validated |
| input media file → decoder | A caller-supplied file is parsed by the platform decoder; a malformed file must produce a typed error, never a crash |
| plugin → filesystem | The engine writes a temp file and moves it into place inside the app's own cache directory |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-14 | Tampering | A job id used as a filename stem without validation, letting a caller write outside the cache directory | high | mitigate | `Compression.startCompress` validates the job id against the same digit-hyphen-hex pattern Android uses before it is ever joined to a path, and rejects anything else with a typed error before any file is touched |
| T-03-15 | Tampering | A caller-supplied input path traversing a symlink to a file the app should not read | high | mitigate | The existing `Arguments.swift` readable-media-file check resolves symlinks and standardises the path before the asset is opened; this plan reuses it rather than adding a second path routine |
| T-03-16 | Denial of Service | A malformed or truncated input crashing the host app through an unhandled AVFoundation failure | high | mitigate | Every AVFoundation call site uses `Probe.swift`'s catch-and-wrap shape so a failure becomes a typed `CompressVideoError`; the full failure-path coverage lands in 03-06 and is exercised against `truncated_mdat.mp4` there |
