**D-11 mapping chosen here** (rationale goes in the dartdoc and in MIGRATION.md):

| `VideoQuality` | `CompressOptions` | Why |
|---|---|---|
| `DefaultQuality` | `preset: CompressPreset.p720` | The incumbent's Android default was short side 720 (1280×720) |
| `LowQuality` | `preset: CompressPreset.p360` | Incumbent: short side 360 |
| `MediumQuality` | `preset: CompressPreset.p480` | Incumbent Android gave 1136×640 and iOS gave Apple's Medium preset (≈480p), so p480 sits between them |
| `HighestQuality` | `preset: CompressPreset.p1080` | Incumbent: no resize at a fixed 3.7 Mbps, which re-encoded 4K blockily. A 1920 cap never upscales, so any source at or below 1080p behaves as "no resize" |
| `Res640x480Quality` | `preset: CompressPreset.p360` | Long side 640 = p360's own cap |
| `Res960x540Quality` | `preset: CompressPreset.p720, maxLongSidePx: 960` | No preset has a 960 cap. The bitrate scales by (960/1280)² from p720 (SizeGuard rule 6) |
| `Res1280x720Quality` | `preset: CompressPreset.p720` | Exact match |
| `Res1920x1080Quality` | `preset: CompressPreset.p1080` | Exact match |

**`compressVideo` parameter mapping** (incumbent units come from its Android `VideoCompressPlugin.kt:142` and iOS `SwiftVideoCompressPlugin.swift:191-199`. `startTime` and `duration` are in **seconds**, and `duration` is the length of the kept span):
`startTime` → `trimStartMs = startTime * 1000`; `duration` → `trimEndMs = ((startTime ?? 0) + duration) * 1000`;
`includeAudio == false` → `AudioStrip()`, otherwise `AudioPassthrough()`; `frameRate` → `maxFps`;
`deleteOrigin == true` → after a successful result, delete the input file only when
`result.outputPath != path`.

**Return types are tightened from nullable to non-null** (`Future<MediaInfo>`, `Future<Uint8List>`,
`Future<bool>`), because the core value is "never returns null". This keeps the incumbent README's
null-unsafe snippet `MediaInfo mediaInfo = await VideoCompress.compressVideo(...)` compiling as
written. An existing `?.` or `!` on the result then gets an analyzer *warning*, not an error.
MIGRATION.md (06-02) says so.
