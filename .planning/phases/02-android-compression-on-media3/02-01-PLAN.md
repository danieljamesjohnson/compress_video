## Decisions this phase implements (IDs used across all seven plans)

`02-CONTEXT.md` records its decisions as prose bullets under four subheadings. They are numbered
here once, and every task in every plan of this phase cites the numbers it implements.

| ID | Decision (abridged from 02-CONTEXT.md `<decisions>`) |
|----|------|
| D-01 | `CompressJob compress(path, {options})` returns a job object immediately; job exposes `id`, `progress` (broadcast 0-100), `result`, `cancel()`, `isCancelled`. No global stream, no in-flight singleton. |
| D-02 | `CompressOptions` immutable const class: `preset` (`p360`/`p480`/`p720` default/`p1080`), `maxLongSidePx`, `videoBitrateBps`, `targetSizeMb`, `maxFps` (30), `audio`, `trimStartMs`/`trimEndMs`, `outputPath`, reserved `codec` (`h264` only) and `hdr` (`toneMapToSdr`). Invalid combinations throw `unsupportedInput` before the channel. |
| D-03 | `CompressResult` immutable, dartdoc on every field: `outputPath`, `inputBytes`, `outputBytes`, `widthPx`, `heightPx`, `durationMs`, `videoCodec`, `audioCodec`, `transmuxed`, `usedOriginal`, `toneMapped`, `hevcFallback`, `audioReencoded`, `elapsedMs`. Never resolves to null. |
| D-04 | `cancel()` completes `result` with `cancelled`, closes `progress`, deletes the partial output before the future completes; cancelling a finished job is a no-op; no result-union type. |
| D-05 | Contract additions: `CompressRequestMessage`, `CompressResultMessage`, `EstimateMessage`; `CompressHostApi` with async `startCompress`/`cancel`/`estimate`/`clearCache`; `@FlutterApi CompressVideoFlutterApi.onProgress(jobId, percent)`. Job ids generated in Dart (monotonic counter + random hex, no new dependency). All three generated outputs regenerated together. |
| D-06 | `CompressVideoErrorReason` gains `encoderUnavailable`, `outOfSpace`, `interrupted`. |
| D-07 | Presets live in `lib/src/presets.dart` as (maxLongSidePx, videoBitrateBps at 30 fps): p360 640/800k, p480 854/1.2M, p720 1280/2.5M, p1080 1920/5M — seeds to be MEASURED and adjusted in this phase, with measured numbers recorded in `doc/PRESETS.md`. |
| D-08 | Never upscale: effective long side = min(requested, input displayed long side); effective fps = min(maxFps, input fps). |
| D-09 | `targetSizeMb` -> video bitrate = (targetBytes x 8 / durationSeconds) - audioBitrateBps - 3% mux overhead, floored at 200 kbps; documented tolerance +/-15%, asserted on the corpus. |
| D-10 | Transmux when input video is H.264, audio is AAC or absent, displayed long side <= target, fps <= cap, and video bitrate <= 1.15 x target bitrate; report `transmuxed: true`; elapsed must be a fraction of an encode. |
| D-11 | Never-larger: pre-check skips the encode when the estimate predicts output >= input; post-check substitutes the original when the finished encode is >= input; `usedOriginal: true`. `small_480p.mp4` is the fixture. |
| D-12 | Frame-rate cap via Media3 `FrameDropEffect` at the effective fps. |
| D-13 | Orientation: Transformer's default handling; re-probe the output with `Probe.kt` so the result's `widthPx`/`heightPx` are displayed dimensions; corpus test asserts 1080x1920 displayed, an upright thumbnail of the output by the pixel-patch method, and no letterboxing via an edge-pixel probe. |
| D-14 | `AudioOptions`: `passthrough` (default), `reencode(bitrateBps, channels)`, `strip`. Passthrough only for MP4-compatible AAC; otherwise re-encode and report `audioReencoded: true`. Strip uses `setRemoveAudio(true)`; re-encode uses `setAudioMimeType(AUDIO_AAC)` plus channel mixing. |
| D-15 | Every file the plugin writes lives under `<cacheDir>/compress_video/`; default output `<jobId>.mp4`; `outputPath` writes exactly there (parent must exist, else `io`); `clearCache()` deletes only that directory's contents; cancelled and failed jobs delete their partial output first. |
| D-16 | Trim: `trimStartMs`/`trimEndMs` in the contract now, implemented on Android with `ClippingConfiguration`; a basic duration-within-one-frame corpus assertion runs in this phase. |
| D-17 | Threading: each job's `Transformer` is created and driven on the main Looper; a `JobRegistry` maps job id to Transformer plus output file; progress polled with `getProgress` every 250 ms on the main handler and forwarded via `onProgress`; the final 100 is sent before the result reply; `onDetachedFromEngine` cancels every live job and deletes partials. |
| D-18 | Error mapping: `ExportException.errorCode` to reason per the table in 02-RESEARCH.md; a pre-flight `StatFs` free-space check (estimate x 1.2) throws `outOfSpace` before encoding; an `ENOSPC` during encode maps to `outOfSpace`; no failure path logs and swallows; every failure path deletes the partial file. |
| D-19 | Estimate: a pure Kotlin `SizeGuard` over probe output plus options returning predicted `outputBytes`, `durationMs`, `widthPx`/`heightPx`, `wouldTransmux`, `wouldUseOriginal` without decoding a frame; exposed as `estimate(path, {options})`; the same function drives the transmux and never-larger pre-checks; tolerance +/-15% against the real encode. |
| D-20 | Build: media3 transformer/effect/common/muxer on the 1.11.x train (02-RESEARCH.md verified 1.11.1 live), minSdk 23, compileSdk 36, AGP 9 built-in Kotlin; CI and a local script assert the example APK's only native libraries are Flutter's own and run a 16 KB alignment check. |

Claude's-discretion items resolved during planning, recorded here so no executor re-decides them:

- **Never-larger substitution always copies.** When the encode is not used, the original bytes are
  copied to the resolved output path (the default `<cacheDir>/compress_video/<jobId>.mp4` when the
  caller gave none). The result's `outputPath` therefore always names a file the plugin owns and
  `clearCache()` can reclaim. Returning the caller's input path instead would mean a caller who
  deletes `outputPath` destroys their original. Document this in the `CompressResult.usedOriginal`
  dartdoc.
- **`AudioOptions` is a sealed class** with three const subclasses, flattened at the channel
  boundary to an `AudioMode` enum plus two nullable integers.
- **Job id format is `<monotonic counter>-<16 lowercase hex characters>`**, generated in Dart with
  `Random.secure()`. Native code treats it as a filename stem and therefore validates it against
  `^[0-9]+-[0-9a-f]{16}$` before use.
- **Progress poll interval is 250 ms**, on the main handler.
