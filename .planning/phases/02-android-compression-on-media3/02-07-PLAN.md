<objective>
Close the phase: a pre-flight estimate that cannot disagree with the real job, a precise and bounded
answer to where this plugin puts files and what `clearCache()` is allowed to delete, and a proof that
the Android build carries no native code and is 16 KB page safe.

Purpose: the estimate exists so an app can tell a user "this will be about 4 MB" before spending
battery on an encode, and it is only trustworthy if it is literally the same arithmetic the encode
uses — which is why it shares one pure function rather than reimplementing the formula. The cache
rules exist because the incumbent's own cache-clearing call has been crashing since 2021 and because
a plugin that sweeps an app's whole cache directory is a defect waiting to be discovered by somebody
else's missing data. The build proof exists because "100 percent native, no FFmpeg" is the reason
developers pick this package, and 16 KB page compliance is table stakes on current Android.
Output: `estimate` and `clearCache` implemented natively, output placement proven, the APK checked,
CI wired, and the toolchain pin recorded.
</objective>

## Flagged assumptions — unresolved probe edges (INFO-03, BULD-01)

Both requirements' edges came back `unclassified` from the deterministic probe and are deliberately
NOT auto-resolved:

- **INFO-03.** The assumption is that the estimate's plus-or-minus 15 percent tolerance holds for the
  clip shapes in this corpus and that a caller can treat it as a general guarantee. It has only been
  measured on synthetic clips on one software encoder. If a real phone's hardware encoder overshoots
  the requested bitrate differently, the documented tolerance is wrong rather than the code. Surface
  this to the developer; Phase 4's hardware checklist is where it gets tested on real silicon.
- **BULD-01.** The assumption is that a debug APK's native-library set is representative of a release
  APK's. 02-RESEARCH.md flagged the 16 KB proof on a release build as an open item. This plan checks
  the debug APK because that is what the local emulator gate builds; whether the release build differs
  is not proven here. Surface it; do not close it by fiat.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller -> plugin (`outputPath`) | A caller-supplied destination path is canonicalised and then written to |
| plugin -> app cache directory | `clearCache()` deletes files on behalf of a host app that did not enumerate them |
| symbolic links inside the cache directory | A link placed inside the plugin's own directory could point outside it |
