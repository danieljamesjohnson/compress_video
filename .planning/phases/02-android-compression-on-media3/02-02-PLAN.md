end to end. Getting the architecture wrong here — the Looper contract Media3 enforces, the per-job
registry that replaces the incumbent's global singleton, the decision to take every result field
from a re-probe rather than from the export's own approximations — is cheap to correct now and
expensive after five more plans are built on top of it. Tasks 1 and 2 define the contract and the
Dart type surface because the tracer cannot cross a channel that does not exist; task 3 is the
tracer itself and nothing in any later plan starts until it is green.
Output: the full compression contract regenerated into all three languages, the public Dart API, and
a working single-preset compression on Android.

## Why the two `one-way` ratings carry no checkpoint

Tasks 1 and 2 are rated `one-way` because the wire field names and the public Dart API names are the
contract Phase 3, Phase 5 and the published Phase 6 package all inherit, and renaming one after
publication is a breaking release rather than a refactor. They carry **no** `checkpoint:decision`
because the developer already walked through this door: every one of these names is written down in
`02-CONTEXT.md`'s locked decisions (D-01, D-02, D-03, D-05). Re-asking would be checkpoint fatigue
over a settled choice. The rating stays so a future reader can see which doors this phase went
through; `verify plan-structure` will warn about the missing checkpoint and that warning is expected
and correct to leave. Do not "fix" it by inserting a checkpoint.

## Flagged assumption — unresolved probe edge (CORE-03)

The deterministic edge probe classified CORE-03's edge as `unclassified` and it is deliberately NOT
auto-resolved here. The assumption this plan proceeds on, recorded so the verifier can challenge it
rather than inherit it silently: **every field of `CompressResult` is non-null on every success path
except `audioCodec`, which is null exactly when the audio track was stripped or the source had none.**
If any other field can legitimately be unknown on some device, this assumption is wrong and the
contract needs a nullable field with a documented sentinel, not a zero. Surface this to the developer
at verification; do not close it by fiat.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller -> plugin (`path`) | A caller-supplied input path is canonicalised and then opened by a platform media codec |
| caller -> plugin (`jobId`) | A caller-generated job id crosses the channel and is used as a filename stem |
| Dart -> native channel | Untyped external callers can reach the generated host API directly, bypassing the Dart-side validation |
| plugin -> app cache directory | Temp and output MP4 files are created in a directory the app owns |
| build -> Google Maven | Four new first-party AAR dependencies enter the build |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-04 | Tampering | `jobId` reaching a filename | high | mitigate | `Compression.startCompress` rejects any job id that does not match digits, a hyphen and sixteen lowercase hex characters before the id is used as a filename stem, so no separator or traversal sequence can reach the filesystem through it |
| T-02-05 | Tampering | `path` reaching a platform codec | high | mitigate | `Arguments.requireReadableMediaFile` canonicalises and then rejects blank, missing, unreadable, non-file and zero-length inputs before any media API is touched; the control is the Phase 1 helper, reused rather than forked |
| T-02-06 | Denial of Service | Untrusted media decoded by the platform codec | high | mitigate | Every terminal outcome arrives through the Transformer listener's two callbacks and is converted to a typed reply; nothing in the engine rethrows a platform exception into the host app, and the partial file is deleted on the error path so a crash loop cannot fill the disk |
