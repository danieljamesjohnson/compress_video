<objective>
Make a compression a job rather than an event: its own progress, its own future, its own cancel, and
a typed reason for every way it can fail — including one real failure produced by a genuinely damaged
file rather than inferred from a javadoc.

Purpose: the incumbent has one global progress stream, one in-flight flag and a compress call that
throws if a second one starts, which is why batch and concurrent use are open issues on its tracker.
Separately, its native failures are caught, printed and returned as `null`, which is the single
largest runtime complaint cluster against it. This plan closes both: per-job everything, and a
mapping table with a test per code so no failure can arrive untyped.
Output: independent per-job progress and cancellation, an exhaustive error mapping, a pre-flight
space check, and partial-file cleanup on every terminal path.
</objective>

## Flagged assumption — unresolved probe edge (CORE-04)

The deterministic edge probe classified CORE-04's edge as `unclassified`; it is deliberately NOT
auto-resolved. The assumption this plan proceeds on comes from 02-RESEARCH.md's Assumptions Log A1 and
A2 and is explicitly a recommendation rather than a verified fact: **a decoder-initialisation failure
means the device lacks a decoder (`decoderUnavailable`) while a decoding-format or decoding failure
means the file is the problem (`unsupportedInput`), and an out-of-space condition is recognised by
matching the underlying cause's message text because Media3 has no dedicated error code for it.**
Task 3 observes one real error code from a genuinely damaged file and records it; if the observed code
contradicts the mapping, change the mapping and say so. Surface this to the developer at verification;
do not close it by fiat.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| untrusted media -> platform codec | A caller-supplied file of unknown integrity is decoded by the device's own codecs |
| plugin -> destination filesystem | Temp and output files are written to a filesystem of unknown remaining capacity |
| caller -> plugin (`jobId` on cancel) | A caller-supplied id is looked up in the live-job registry |
| host app lifecycle -> running exporters | The Flutter engine can detach while exporters are still running |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-21 | Denial of Service | A malformed or truncated input crashing the host app through the platform codec | high | mitigate | Every terminal outcome arrives through the exporter's two listener callbacks and is converted by `ErrorMapping` into a typed reply; no platform exception is rethrown into the host app, and the damaged-clip integration case proves it on a real file rather than in theory |
| T-02-22 | Denial of Service | Disk exhaustion from an encode that cannot fit, or from partial files accumulating across failures | high | mitigate | A pre-flight free-space check against 1.2 times the predicted output fails the job before a Transformer exists; every failure and cancellation path deletes the temp file before replying; and an out-of-space condition arising mid-encode maps to the dedicated reason |
