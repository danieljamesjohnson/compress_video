<objective>
Create the `compress_video` plugin package itself: the Flutter plugin scaffold, the hand-built
shared `darwin/` Apple tree that serves iOS and macOS from one source directory and one
manifest each, the typed error taxonomy the whole plugin throws, and the CI workflow that keeps
all of it building on a Linux runner and a macOS runner.

Purpose: the current Flutter 3.44 plugin template does **not** produce a shared `darwin/` tree —
it emits separate `ios/` and `macos/` packages — so the layout CONTEXT.md requires has to be
assembled by hand. That hand-built layout is the single riskiest artifact of the phase and cannot
be compiled on danserver at all, so CI exists from this plan onward specifically to prove it
before any Swift implementation is written on top of it.
Output: a package that analyses clean, publishes clean, builds an APK, builds for iOS and macOS
through both CocoaPods and Swift Package Manager, and runs its unit tests on both runners.
</objective>
