## Contract decisions this plan fixes (record them in the SUMMARY)

CONTEXT.md leaves the out-of-range behaviour to Claude's discretion. These are the choices, and the
reasoning, so a later reader does not have to guess:

- **`positionMs < 0` is an error (`unsupportedInput`).** There is no frame before the start of a
  clip, so a negative position is a caller bug and silently clamping it would hide that bug.
- **`positionMs > durationMs` clamps to the last frame.** Duration reporting is approximate at the
  millisecond level and callers routinely compute a position from a duration they read earlier;
  both platforms' frame APIs already clamp, so erroring here would be hostile and would also make
  the two platforms disagree.
- **`quality` must be 1 to 100 inclusive**, matching the JPEG quality range the option name
  promises; anything else is `unsupportedInput`.
- **`maxDimensionPx` caps the longer displayed side, never upscales, and must be positive**; `null`
  means no cap.
- **Unique thumbnail names** are `compress_video_thumb_<epoch millis>_<8 random hex>.jpg` inside a
  `compress_video` subdirectory of the app cache directory.
- **`getThumbnail` returns `Uint8List` and `getThumbnailFile` returns a `String` path** — no
  wrapper model type, as fixed in plan 01-04.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| caller → plugin (`outputPath`) | A caller-supplied destination path is canonicalised and then written to |
| plugin → app cache directory | Thumbnail JPEGs are created in a directory the app owns and other apps cannot read |
| caller → plugin (`maxDimensionPx`) | A caller-supplied size drives a bitmap allocation |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-11 | Tampering | `outputPath` traversal reaching an unintended file | high | mitigate | `Arguments.kt` canonicalises `outputPath` and requires an existing, writable parent directory before any bytes are written; the write goes to a temporary file that is renamed into place, so a rejected path never leaves a partial file. The write is bounded by the host app's own sandbox in any case — the control turns a traversal attempt into a typed `io` error rather than an unexpected native failure |
| T-01-12 | Information Disclosure | Thumbnail JPEG placement | medium | mitigate | The default destination is a `compress_video` subdirectory of `context.cacheDir`, which is app-private on Android. The plugin never writes to external or shared storage and never requests a storage permission |
| T-01-13 | Denial of Service | Unbounded `maxDimensionPx` driving a bitmap allocation | medium | mitigate | `maxDimensionPx` only ever caps the frame: `MediaMath.scaledSize` never returns a dimension larger than the source frame, so a huge value cannot cause an allocation larger than the decoded frame itself. Non-positive values are rejected before any decode |
| T-01-23 | Tampering | The caller's input video file | high | mitigate | The input is opened read-only on every path; no code path moves, renames, truncates or deletes it, and the integration suite asserts its length and modification time are unchanged after every thumbnail call. This is the explicit prohibition recorded in this plan's `must_haves` |
</threat_model>
