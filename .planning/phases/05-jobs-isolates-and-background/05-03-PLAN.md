<objective>
Let an Android caller opt a job into a `mediaProcessing` foreground service so the encode survives
the app going to the background, and make the system's own six-hour quota expiry resolve those
jobs as retryable rather than as a mystery.

Purpose: JOBS-05's Android half is the requirement that decides whether this plugin is usable for
the upload-in-the-background flows it is aimed at. It is also the one place in the phase where
getting the lifecycle wrong is worse than not shipping it — a service that outlives its jobs burns
the user's battery and the app's quota, and a service that fails to stop after `onTimeout` is an
ANR the system names in the crash.
Output: one options object, one manifest declaration, one ref-counted service with a correct
`onTimeout`, the `interrupted` reason thrown for real on Android, and an emulator proof that
backgrounds the app mid-encode.
</objective>

## Decisions implemented here

See `05-01-PLAN.md` → "Decision map". This plan implements **D-07**, **D-08**, **D-09**, **D-10**,
and resolves the discretion items **D-15** (notification channel identity and default strings) and
**D-16** (started versus bound service).

### Discretion resolved here

- **D-16: a started service, not a bound one.** It must survive the Activity going away, which is
  the whole point; binding would tie its lifetime to a component that is precisely what disappears.
  It stops itself via `stopSelf` when its hosted-job count reaches zero.
- **D-15:** notification channel id `compress_video_media_processing`, user-visible channel name
  "Video compression", importance low (no sound, no heads-up). Default title "Compressing video"
  and default text "1 video" / "N videos" derived from the hosted count when the caller's options
  leave them blank — the caller's own title and text win whenever supplied.

### Research override: no AndroidX Core notification helper

05-RESEARCH.md's Core table names `androidx.core.app.NotificationCompat`. This plan uses the
platform's own `Notification.Builder` and `NotificationChannel` instead. `android/build.gradle.kts`
declares no direct `androidx.core` dependency — it would arrive only transitively through Media3 —
and adding one would contradict this phase's "no new dependency" finding for a class whose only job
here is to build a notification that, by D-08, is never constructed below API 35 anyway. Both
platform APIs are unconditionally available at that level, so the compatibility wrapper buys
nothing. Record this override in the summary.
