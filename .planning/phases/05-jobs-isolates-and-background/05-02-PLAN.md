## Decisions implemented here

See `05-01-PLAN.md` → "Decision map" for the full table. This plan implements **D-05** (the static
`ensureInitializedInBackgroundIsolate` convenience and nothing else new) and **D-06** (the
`Isolate.run` proof on all three platforms plus the omitted-initialisation typed-error case), and
must not regress **D-01**–**D-04** from 05-01.

<assumption_delta_decision>
**Noun that changes primacy:** `isolate` — every call in this package was implicitly a root-isolate
call (the default binary messenger, the module-level job registry, the per-messenger Flutter API
registry in `compress_job.dart`) and becomes *any isolate*.

**Decision: `add-alongside`, not `promote`.** The root isolate stays the primary and default
context: `binaryMessenger` remains an optional parameter defaulting to the platform default,
nothing in the package's shape changes, and the background case is reached by one documented
static call the caller makes. Promoting the plural noun — for example making the plugin own an
isolate, or requiring every caller to pass a token — would add surface for a case most apps never
hit, and 05-CONTEXT.md explicitly caps this requirement's public API addition at "one static
initialiser".

**One consequence to verify rather than assume:** `compress_job.dart`'s `_jobRegistry` and
`_flutterApiRegistry` are module-level, and module-level state is *per isolate* in Dart. That is
correct rather than broken here — a job started on a background isolate registers in that
isolate's own map and its progress callbacks arrive on that isolate's own messenger — but it means
a job started on one isolate is invisible to another, which the suite must assert rather than
leave implied.

**Invariant test warranted: yes.** Task 1's case asserts, for the job run inside `Isolate.run`,
the same per-job invariant 05-01 asserts for a queued job: progress non-decreasing within 0–100,
stream closing before or as the result settles, and a result carrying that job's own output path.
The same helper shape is used, so "regardless of isolate" is proven by the same assertions as
"regardless of queue position".
</assumption_delta_decision>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| root isolate → spawned isolate | A `RootIsolateToken` crosses this boundary; it is an opaque engine-issued handle, not caller data (05-RESEARCH.md Security Domain, V5) |
| background isolate → platform channel | An uninitialised isolate's platform call reaches the engine's message plumbing with no messenger bound |
| new suite → CI runner budget | Every Apple-relevant push now executes one more suite inside a fixed, unraisable step budget |
